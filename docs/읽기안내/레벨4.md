<a id="guide-intro"></a>

## 프로젝트 소개

**모델 아키텍처의 표현력뿐 아니라 입력 전처리와 학습 정책이 결과에 영향을 줄 수 있습니다.**

YOLO와 ViT/CNN의 입력 크기가 다르므로, 이 비교를 동일 계산 조건의 구조 비교로 단순화하지 않습니다.

분류 성능과 배포 비용의 비교를 분리해 읽습니다.


<a id="guide-problem"></a>

## 문제와 주요 기능

| 확인 대상 | 설명 |
| --- | --- |
| **모델 선택 목표** | 모델 선택은 F1을 높이는 문제와 지연·메모리를 낮추는 문제를 함께 가집니다. |
| 전처리·종료 차이 | 하지만 서로 다른 전처리 해상도와 조기 종료 설명이 섞여 있어 아키텍처만의 효과를 분리하기 어렵습니다. |
| 지표와 조건 | 지표별 장단점과 비교 조건을 함께 제시해야 합니다. |

## LEVEL 4 · 조건과 절차를 상세히 읽기

<a id="semantic-classification-level-4"></a>

### LEVEL 4 · 자료 분할과 세 분류기의 비교

비교 단위는 영상 이진 분류기입니다.

입력 해상도와 학습 정책이 모델별로 달라 구조 자체의 효과와 전처리 효과가 섞일 수 있습니다.

**흠집·오염 예시는 오류 해석의 근거**이며 다중 결함 위치 추정이나 현장 전체 결함 검증으로 확장하지 않습니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-3-row-1"></a> 약 2,000장 OK/NG·80:20 | OK 는 정상, NG는 불량입니다.<br>사진의 약 80%는 모델이 규칙을 배우는 데, 나머지 약 20%는 그 규칙을 확인하는 데 씁니다.<br>별도 외부 공장 시험을 뜻하지 않습니다. |
| <a id="layout18-table-3-row-2"></a> YOLOv8·ViT·자체 CNN | 세 모델 모두 사진 전체를 정상/불량으로 분류합니다.<br>볼 위치를 찾는 탐지 결과와 구분합니다.<br>금속 표면 흠집·오염의 예시가 모든 결함 종류를 포괄하지는 않습니다. |
| <a id="layout18-table-3-row-3"></a> 정확도·정밀도·재현율·F1 | 정확도는 전체 판정, 정밀 도는 불량으로 지목한 것의 적중, 재현율은 실제 불량을 찾은 정도를 봅니다.<br>F1은 정밀도와 재현율을 함께 요약하지만 오류 종류를 없애지는 않습니다. |


<a id="semantic-models-level-4"></a>

### LEVEL 4 · 입력 크기와 학습 설정의 의미

CNN의 지역적 무늬 처리, ViT 사전 학습 표현, YOLO 분류 경로의 차이를 해상도·학습 정책과 분리해 봅니다.

**입력 크기 통제 없이 관측 차이를 아키텍처 하나의 인과 효과로 해석할 수 없습니다.**

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-4-row-1"></a> YOLOv8 입력 64·batch32 | 입력 크기는 모델에 넣을 사진의 크기 설정, batch32는 한 번의 갱신에 묶는 사진 수입니다.<br>원고 호출의 설정이지 모든 모델의 공통 설정은 아닙니다. |
| <a id="layout18-table-4-row-2"></a> 최대 3,000epoch·patience100 | epoch 는 학습 자료를 반복해 보는 단위입니다. 3,000은 최대 반복 한도이고 patience100은 개선을 기다린 뒤 일찍 멈추는 설정입니다.<br>실제 3,000회를 모두 완료했다는 뜻은 아닙니다. |
| <a id="layout18-table-4-row-3"></a> ViT 224×224·google/vit-base-patch16-224-in21k | 사전 학습된 Vision Transformer를 분류에 이용합니다.<br>YOLO 입력 64와 같게 줄인 사진의 비교가 아닙니다. |
| <a id="layout18-table-4-row-4"></a> 자체 CNN 224×224·합성곱/풀링 3 블록·완전연결층 | 합성곱이 무늬를 찾고 풀링이 공간 정보를 줄인 뒤 완전 연결층이 분류합니다.<br>원고의 구성 설명이며 실행 패키지가 제공됐다는 뜻은 아닙니다. |


<a id="semantic-cost-level-4"></a>

### LEVEL 4 · F1·속도·용량을 함께 읽기

품질과 메모리·지연을 각각 검토해야 합니다.

**약 4MB CNN의 저장 비용과 22ms 처리 시간은 같은 축이 아닙니다.**

해당 장비·측정 범위를 넘는 처리량이나 라인 지연은 별도 계측이 필요합니다.

| 조건·자료 | 의미와 확인 방법 |
| --- | --- |
| <a id="layout18-table-5-row-1"></a> 5 쪽 표·6 쪽 결론의 YOLOv8 | F1 0.972·12ms·약 15MB입니다.<br>F1은 분류 지표, ms는 처리 시간, MB는 모델 크기라 서로 다른 성질을 뜻합니다. |
| <a id="layout18-table-5-row-2"></a> 같은 보고의 ViT | F1 0.958·28ms·약 380MB입니다.<br>더 큰 모델이 이 표에서 더 높은 F1을 얻은 것은 아닙니다. |
| <a id="layout18-table-5-row-3"></a> 같은 보고의 CNN | F1 0.943·22ms·약 4MB입니다.<br>작은 저장 크기와 분류 지표를 함께 비교하되 다른 장비에서도 이 시간이 유지된다고 보장하지 않습니다. |
| <a id="layout18-table-5-row-4"></a> 자료 범위 | 원고 PDF와 같은 판의 편집 원본은 로컬에 보존하며 공개하지 않습니다. 공개 문서는 연구 방법·보고값·한계를 설명합니다.<br>제조 원영상 전체·가중치·학습 로그·완성된 검사 실행 패키지는 제공하지 않습니다. |


<a id="semantic-conflicts-level-4"></a>

### LEVEL 4 · 원고 내부 차이와 재실행의 경계

최대 epoch만으로 종료 상태를 결정할 수 없으며 ViT 정책의 불일치는 비교 조건의 불확실성입니다.

현장 확장 시 전처리·학습·시간 측정·외부 평가를 각각 설계해야하나 현재 자료가 그 구현을 제공하는 것은 아닙니다.
